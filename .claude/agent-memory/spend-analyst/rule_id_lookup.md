rules.json is regenerated by /extract-rules, and rule_ids shift between extractions (App C rows D/E/F moved by one or two
numbers on 2026-10-17, so hard-coded IDs in analyse.py cited the wrong rules).
**Why:** a stale ID silently mis-cites a rule; QA traces citations. **How to apply:** analyse.py uses
`rule_ids_for_clause(rules, "App C row D")` (stops if the clause is missing) and anti-avoidance IDs by `type`;
selfcheck.py reads the threshold under test from analytics.json. Grep scripts for `CPR-` and literal threshold
values before each run. Clause 1.6.2 (grant = contract) sits in rules.json `excluded`, so it has no rule_id.

Update 2026-10-19: found analyse.py again carrying literal CPR-12/61/62/63 and selfcheck.py literal 25000/22500 (the
earlier fix had been lost). Re-fixed: `rule_ids_for_clause`, `anti_avoidance_ids`, and selfcheck reads the threshold from
analytics.json. **How to apply:** `grep -n 'CPR-\|25000' scripts/*.py` before every run; never trust that a past fix persists.
